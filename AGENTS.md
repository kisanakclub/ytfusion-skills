# Maintaining this skill package

Keep reusable operating procedures here and user collections outside this repo.
Do not embed installation paths, credentials, real channel allocations, private
provider engines or an owner's production ledger.

Use the native installed HDS workflow. Read the relevant skill reference before
changing its procedure. Preserve user choices instead of turning one production
wave's counts, providers or storage budget into fixed requirements.

Run the stdlib tests for helper changes. Validate the skill manifest and relative
references when editing the package. Verify examples against meaningful scenarios:
new Master, existing independent collection, unavailable Shared provider, title
reuse and resuming partial output. Never buy generation for package validation.

Do not publish unrelated files or claim live cross-agent/device verification
from a structural check or a fixture test.

For assigned app/skill maintenance, use the
[maintenance map](skills/ytfusion-operations/references/skill-maintenance.md).
Compare the relevant current app source and existing skill diff before editing.
Keep behavior, data/action contracts, onboarding prompts and visual references
consistent; check only the guides affected by the change. An internal source
change can leave a guide unchanged when the operating instructions still hold;
record that decision briefly rather than adding generic guidance.

Use synthetic accounts/data for maintained UI captures and record their source
revision. Do not publish an owner's live screenshots or hardcode pilot settings.
Refresh screenshots when the referenced UI changes; preserve the written
behavior/accessibility contract and adapt to the assigned host's capabilities.
Treat app push, skill push, installed skill/discovery, and a migrated executor or
dashboard as separate results. A routine operator assignment does not authorize
source/skill authorship or deployment on other hosts.
